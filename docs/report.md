# Отчёт: мультиагентная система принятия продуктовых решений

## 1. Постановка

Тема: моделирование продуктовой разработки - принятие решений с помощью
мультиагентной системы. На вход - описание продуктовой ситуации, на выход -
обоснованное решение, прошедшее цикл согласования виртуальной команды.

## 2. Архитектура

Конвейер: RAG-контекст (глоссарий + похожие кейсы, BM25 + векторный -> RRF)
-> Analyst (черновик) -> Validator (rule-based) -> Critic (LLM-as-a-Judge)
-> Editor -> цикл Supervisor'а с адаптивным бюджетом и rollback.
L2-бэкенды: Ollama (qwen2.5:7b) с fallback на HuggingFace. HITL: подтверждённое
продакт-владельцем решение попадает в Decision Memory (active learning).

## 3. Ablation-эксперименты (8 режимов)

Режимы моделируют состав команды: baseline (только модель), glossary, tm,
tm_hybrid, agents_only, tm_hybrid_critic, tm_hybrid_editor, full.

## 5. Качество retrieval

Recall@1 / Recall@5 / MRR по каналам на 200 парах запрос-эталон
(`python scripts/eval_retrieval.py --limit 200`; эмбеддинги
paraphrase-multilingual-MiniLM-L12-v2, Qdrant 1300 кейсов, BM25 по situation+outcome):

| Канал | recall@1 | recall@5 | MRR | Запросов |
| --- | --- | --- | --- | --- |
| BM25 | 0.87 | 1.00 | 0.93 | 200 |
| Векторный | 0.49 | 0.92 | 0.67 | 200 |
| RRF (гибрид) | 0.69 | 0.98 | 0.83 | 200 |

BM25 ожидаемо доминирует: пары генерируются шаблонной парафразой situation,
лексическое пересечение велико. Векторный канал хуже в @1 (модель легче
различает тематику, чем формулировку), но почти не уступает в @5. RRF
усредняет каналы: @5 = 0.98 (чуть ниже BM25 из-за векторного шума в топе),
но устойчивее к запросам без лексического пересечения - поэтому гибрид
оставлен в продакшн-конфигурации.

## 6. Калибровка порога similarity

`python scripts/calibrate_threshold.py --samples 15000` (seed 42; 100 сэмплов
мало - hit-rate "used" при случайной паре кейс-термин всего ~0.4%):

| Параметр | Значение |
| --- | --- |
| n сэмплов | 15000 |
| min score "used" | 1.000 (все реальные вхождения ловит substring-путь) |
| max score "unused" | 0.642 |
| ошибка при пороге 0.7 | 0.0 |
| ошибка при пороге 0.82 | 0.0 |

Классы разделены идеально: весь "unused"-массив ниже 0.65, весь "used" равен
1.0. Порог 0.7 лежит внутри разделяющего зазора с запасом, ошибка 0% -
**текущий порог 0.7 подтверждается**. Предложение скрипта (0.82, середина
зазора) решений на этих данных не меняет; 0.7 оставлен как более мягкий
вариант для парафразированных употреблений термина.

## 7. Инфраструктура и эксплуатация

Docker Compose (8 сервисов), nginx с security headers, health-checks,
readiness /health, кэш решений с составным ключом.

По retrieval-контуру (разделы 5-6):
- BM25 на шаблонных парафразах почти идеален (recall@5 = 1.00), поэтому
  качество гибрида упирается в векторный канал: его @1 = 0.49 - главный
  резерв улучшения (более тяжёлая мультиязычная модель эмбеддингов).
- Гибрид RRF устойчивее моно-каналов на запросах без лексического
  пересечения - оставлен в продакшн-конфигурации; деградация до BM25 при
  недоступном Qdrant проверена (retrieval_backend в ответе /decide).
- Порог similarity 0.7 подтверждён калибровкой на 15000 пар: классы
  used/unused разделены с нулевой ошибкой.
- Decision Memory (1300 кейсов) заливается идемпотентно (повторный импорт:
  создано 0, пропущено 1300); HITL-подтверждения расширяют память -
  активное обучение на реальных решениях.
